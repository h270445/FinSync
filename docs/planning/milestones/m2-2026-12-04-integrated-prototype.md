## Acceptance criteria

- [ ] All sources go through the same matching pipeline: Android notifications (one bank format), spreadsheet-export files and manual entries (Google Sheets rows if the script is built).
- [x] Demo: a notification on the phone and the same purchase imported from a spreadsheet appear as one event, while two separate purchases of the same amount on the same day stay two events. (2026-11-24: demo seed `python -m finsync.api.demo` and [demo guide](../../guides/demo.md), checked through the service and in the browser on synthetic data; 2026-11-24: run with the Android emulator on the author's computer, the notification posted on the emulator and the bank export linked into the same PELDABOLT event, the two MINTA KAVEZO purchases kept apart, the overview totals as in the guide; android-emulator-e2e skill 1.2, demo mode; tried by the author the same day.)
- [ ] Uncertain matches can be listed, confirmed and rejected in the web app; a wrong link can be split; every action is logged and supersedes the previous decision.
- [x] Requests are authenticated: per-user API tokens for the Android app (and Sheets script), password login with a secure session cookie and CSRF protection for the web app; client-supplied identity headers are no longer trusted (tokens 2026-11-02, web sign-in 2026-11-12, [ADR 0010](../../architecture/decisions/0010-web-sign-in.md); actions that widen access, token management and role changes, only from the web session since 2026-11-23, [ADR 0012](../../architecture/decisions/0012-no-multi-factor-authentication.md)).
- [x] Every endpoint has a cross-group access test (403/404, nothing written) (`tests/test_auth.py`, 2026-11-02).
- [ ] Malformed input, oversized bodies and failing bulk imports leave the database unchanged and return a clear error: 400 for malformed input, 413 for an oversized body (`tests/test_api_limits.py`, 2026-11-07; failing bulk imports were already atomic).
- [x] The LLM categorizer runs behind the same interface as the rule-based one and its output is validated against the category list. (2026-11-19: LLM layer built and tested with output validation, used by the measurement; 2026-11-24: called in the live flow by the group's schedule or "ask now", [design](../../design/categorization.md#when-the-llm-is-called-proposed-by-the-author-2026-11-19), `tests/test_llm_live.py`.)

(Both layers built 2026-11-19; measured 2026-11-24, [report](../../evaluation/results/2026-11-24-categorization-hybrid.md); LLM wired into the core 2026-11-24; report read by the author 2026-11-24.)
